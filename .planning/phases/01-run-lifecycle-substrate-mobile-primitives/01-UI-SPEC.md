## New Tokens (extending `src/styles/tokens.css`)

These tokens are NEW for Phase 1. They must coexist with every existing token — do not modify existing values. Comments document the role for the Phase 3 audit.

### Breakpoints (MOB-02)

```css
:root {
  --bp-sm: 480px;   /* small phones — currently no behavior; reserved */
  --bp-md: 768px;   /* THE breakpoint — desktop/tablet split */
  --bp-lg: 1024px;  /* desktop expansion threshold */
}
```

CSS usage: `@media (max-width: 767.98px)` for `<md` queries (use `767.98px` not `767px` to avoid the 1px gap that misclassifies fractional viewports). JS usage: `useViewportLte('md')` hook reads `window.matchMedia('(max-width: 767px)')`.

### Safe-area helpers (MOB-02)

```css
:root {
  --safe-top: env(safe-area-inset-top, 0px);
  --safe-right: env(safe-area-inset-right, 0px);
  --safe-bottom: env(safe-area-inset-bottom, 0px);
  --safe-left: env(safe-area-inset-left, 0px);
}
```

The viewport meta in `app/layout.tsx` MUST set `viewport-fit=cover` for these to resolve to non-zero on iOS notched devices.

### Touch-target minimum (informs MOB-09 audit in P3)

```css
:root {
  --touch-target-min: 44px;
}
```

Component CSS that exposes a tap target uses `min-height: var(--touch-target-min); min-width: var(--touch-target-min);` — preferred over hard-coding `44px` so the value can be updated globally.

### Mobile-shell role tokens (NEW)

### Z-index tier (REPLACES the existing flat list — STRICTLY ordered)

The existing `tokens.css` ships `--z-dropdown 100` / `--z-sticky 200` / `--z-modal 300` / `--z-toast 400` / `--z-tooltip 500`. Phase 1 keeps those values and adds three new tiers with explicit ordering rationale, so future phases (push toasts P5, plan-review modal P4, ghost-card overlays P5) don't compete for z-index by accident:

```css
:root {
  /* Existing — DO NOT change values */
  --z-dropdown: 100;        /* dropdown menus, popovers */
  --z-sticky: 200;          /* desktop Sidebar, sticky table headers */
  --z-bottom-tab: 250;      /* NEW — sits BELOW modal-class surfaces but ABOVE base content */
  --z-mobile-topbar: 260;   /* NEW — sits just above bottom tab when both visible */
  --z-modal: 300;           /* existing modal overlay (CardDetailModal etc.) */
  --z-sheet: 320;           /* NEW — vaul BottomSheet portal; one tier above legacy modal */
  --z-drawer: 340;          /* NEW — vaul Drawer (sidebar replacement); above BottomSheet so a Drawer opened from inside a sheet wins */
  --z-toast: 400;           /* existing — Sonner stack (P3) */
  --z-tooltip: 500;         /* existing */
}
```

**Stacking contract (locked):** Drawer (340) > Sheet (320) > Modal (300) > Mobile Topbar (260) > Bottom Tab (250) > Sticky (200) > Dropdown (100). Any future surface MUST slot into this ladder, not append a new tier.

## Spacing Scale

Per `DESIGN.md` §5 the design system is anchored on an 8px base with established mid-step values. The existing `tokens.css` ships `--space-1..--space-16` (0.25rem..4rem). **Phase 1 reuses the existing scale exactly — no new spacing tokens, no mobile-only overrides.**

| Token | Value | Usage in Phase 1 primitives |
|-------|-------|------------------------------|
| `--space-1` | 4px | Tab bar icon→label gap |
| `--space-2` | 8px | BottomSheet body internal vertical gap |
| `--space-3` | 12px | Drawer item padding (matches Sidebar `.item`) |
| `--space-4` | 16px | Default container padding (matches Sidebar header) |
| `--space-5` | 20px | (unused this phase) |
| `--space-6` | 24px | BottomSheet body horizontal padding (matches `.card-detail-header`) |
| `--space-8` | 32px | (unused this phase) |
| `--space-10..16` | 40..64px | (not used in primitives; long-form layout in P3/P5) |

**Per CONTEXT D-02 (Density Preserved):** there are NO mobile-only spacing overrides. The same `--space-*` values apply at 375×667 and 1440×900. Touch targets reach the 44pt minimum via `min-height: var(--touch-target-min)` on the interactive element, NOT by inflating padding into the spacing scale. The plan-checker has a contract test (`tests/compat/mobile-primitives.test.ts` case 4) that fails CI if any new `@media (max-width: …)` rule contains a `font-size:` or `line-height:` declaration. Spacing is similarly locked by convention; the same audit catches accidental drift.

**Exceptions:**
- BottomSheet drag-handle area uses `--sheet-handle-height: 4px` and a 12px vertical padding zone — the visible handle is 4px but the touch zone is the full top 24px so users can grab it without precision. Implemented inside the sheet header; not a global token.
- Bottom tab cells: each tab cell has `padding: 8px 12px` (i.e., `--space-2 --space-3`) which produces a 56px tall (`--bottom-tab-height`) interactive box with the 20px icon + 12px label stack. Already meets `--touch-target-min`.

## Component Specs

### 1. Mobile Topbar (mobile-mode at <768px)

The existing app shell has a desktop sidebar that dominates the chrome. At <768px the sidebar collapses into a Drawer; the Topbar takes over as the persistent header.

**Anatomy:**

```
┌────────────────────────────────────────────────┐
│ [☰]   Project name (or "Co-Op")          [👤] │  ← --topbar-height (56px)
└────────────────────────────────────────────────┘
```

**Specifics:**
- Height: `var(--topbar-height)` (56px — same as desktop, DO NOT inflate)
- Background: `var(--mobile-topbar-bg)` (Carbon Surface)
- Border-bottom: `1px solid var(--mobile-topbar-border)`
- Padding: `0 var(--space-3)` (12px horizontal)
- Z-index: `var(--z-mobile-topbar)` (260)
- Padding-top extension: when iOS notch present, `padding-top: var(--safe-top)` and `height: calc(var(--topbar-height) + var(--safe-top))`. Background extends into the safe area.
- Layout: 3-cell flex row — left cell `auto` (hamburger), center cell `1fr` (project name), right cell `auto` (avatar/profile).

**Left cell — hamburger button:**
- 44×44pt tap target (`min-height/width: var(--touch-target-min)`)
- Icon: `lucide-react Menu` at 20px, color `var(--color-text-secondary)`
- `aria-label="Open navigation menu"` — exact string, not "Menu" (screen readers without context)
- `aria-expanded={drawerOpen}` — bound to drawer state
- `aria-controls="mobile-nav-drawer"` — drawer root has matching `id`
- `:hover` → background `var(--color-bg-hover)` + icon color `var(--color-text-primary)` (matches `Sidebar.module.css .toggle:hover`)
- `:focus-visible` → outline `2px solid var(--color-accent)` + outline-offset 2px
- `:active` → `transform: scale(0.97)` (matches existing `.btn:active`)

**Center cell — project name (or app name fallback):**
- When inside a project route (`/p/[projectId]/...`): displays `currentProject.name`
- When outside a project route (`/`, `/login`, etc.): displays `"Co-Op"` (the app name; matches existing `.logoText`)
- Font: `var(--font-size-md)` 16px Inter weight 500 color `var(--color-text-primary)`
- Truncation: `overflow: hidden; text-overflow: ellipsis; white-space: nowrap; max-width: 100%;` — center-aligned via flex `justify-content: center`. Single line, ellipsis on overflow. (At 375px viewport with 44px hamburger + 44px avatar + 24px gutters, the center cell is ~219px wide; ~18 chars before ellipsis.)
- NOT clickable in Phase 1 (no project switcher inline). The project switcher lives inside the Drawer (Sidebar already has it). P3/P5 may add a tap-to-switch affordance — **out of scope here**.

**Right cell — profile avatar:**
- Reuses the existing `.avatar` class from `globals.css` at default 32px size
- Wrapped in a 44×44pt tap target — clicking opens the user menu (sign-out, theme toggle). Behavior identical to existing Sidebar footer user area.
- For Phase 1, the right cell can render the avatar non-interactively if a popover menu is more than the phase budget — Drawer footer already exposes sign-out, so the avatar is decorative-only by default. **Decision:** ship as decorative in P1; P3/P5 add the popover when settings/profile mobile pass lands.

**Coexistence with desktop Sidebar:**
- The existing fixed-position Sidebar at `--sidebar-width: 260px` collapsed-or-expanded uses `--sidebar-current-width` CSS variable to push main content. **At <768px, the Sidebar component returns `<MobileNav>` instead** — `--sidebar-current-width` MUST be set to `0` in mobile mode so existing layouts don't reserve sidebar space. The hook `useViewportLte('md')` triggers the swap; the side-effect `useEffect` in `Sidebar.tsx` updates `--sidebar-current-width` accordingly.
- Project shell `(dashboard)/p/[projectId]/layout.tsx` MUST add `padding-top: var(--topbar-height)` to its main scroll container at <768px so content clears the fixed Topbar. Add `padding-bottom: calc(var(--bottom-tab-height) + var(--safe-bottom))` to clear the Bottom Tab Bar. Existing desktop layout is unaffected (fixed Topbar is mobile-only).

Replaces the desktop fixed Sidebar at <768px. Triggered by hamburger; closes via backdrop tap, ESC, swipe-to-close, or route change.

**Anatomy:**

```
│ Co-Op  ●  [✕]          │  ← Drawer header (matches Sidebar.module.css .header)
├────────────────────────┤

│  ▷ Settings            │

│ [Project Switcher ▾]   │
│ [Avatar] User · Sign-out│

←─── --drawer-width ───→
```

**Specifics:**
- Direction: `left` (vaul `Drawer.Root direction="left"`)
- Width: `var(--drawer-width)` = `min(85vw, 320px)`. At 375px viewport this resolves to ~319px (essentially full-width minus 8% peek of the page underneath, so users see the visual stack).
- Background: `var(--drawer-bg)` (Carbon Surface)
- Border-right: `1px solid var(--drawer-border)`
- Z-index: `var(--z-drawer)` (340)
- Overlay: `var(--drawer-overlay)` `rgba(0,0,0,0.7)` — covers full viewport including Topbar
- Content: render the existing `Sidebar.tsx` body inside the drawer. Component composition — do NOT duplicate the nav structure. The Sidebar component branches: `isMobile ? <Drawer.Root>...sidebarContents...</Drawer.Root> : <aside className="sidebar">{sidebarContents}</aside>`.
- Padding-top: `var(--safe-top)` so content clears notch when drawer is full-height
- Padding-bottom: `var(--safe-bottom)` for iOS home indicator clearance
- Animation: vaul defaults (slide-in from left, ~300ms with spring). Honored automatically by `prefers-reduced-motion` — no override.
- Drag-to-close: `dismissible={true}` (vaul default) — swipe leftward closes; swipe rightward expands but caps at full width.

**Triggers (open):**
- Hamburger tap in Mobile Topbar (primary)
- Edge-swipe from left of viewport (vaul native)
- (P3/P5 may add: `Cmd+\\` keyboard shortcut — out of P1)

**Dismissals (close):**
- Backdrop tap (vaul default, `modal=true`)
- ESC key (vaul default, focus-trapped)
- Swipe leftward (vaul drag handler)
- Route change — listen to `usePathname` changes; close on transition. Implemented in `MobileNav.tsx` via a `useEffect` watching pathname with `setOpen(false)` on change.
- Programmatic close after a project-switcher selection (the existing switcher already calls `router.push` — wire `onClose` after navigation)

**Active-state styling:** the in-drawer nav uses **the existing `Sidebar.module.css .itemActive` styles unchanged** — `background: var(--color-accent-muted)` + `color: var(--color-accent)` + 3px `.indicator` pill. This phase does NOT introduce a new active state for the Drawer; it reuses Sidebar's. Visual parity desktop ↔ mobile.

**Focus management:**
- vaul's `Drawer.Root` traps focus in the open drawer (Radix Dialog underneath)
- First focusable element gets focus on open (the close button `[✕]` in the drawer header)
- On close, focus returns to the hamburger button (vaul handles this; verify in test fixture)

### 3. BottomSheet (vaul-backed modal replacement)

Replaces `CardDetailModal` at <768px in Phase 1. Other modals (`AgentHarnessModal`, settings modals, plan-review modal) adopt the same primitive in P3/P4/P5.

**Anatomy:**

```
            [overlay #00000080]
            ┌────────────────────────┐
            │       ━━━━             │  ← drag-handle (--sheet-handle, 40×4px)
            │ Title           [✕]    │  ← sticky header
            ├────────────────────────┤
            │                        │
            │   Scrollable body      │
            │   (--space-6 padding)  │
            │                        │
            ├────────────────────────┤
            │  [Cancel]   [ Save  ]  │  ← sticky footer (primary action)
            └────────────────────────┘
```

**Specifics:**
- Direction: `bottom` (vaul `Drawer.Root direction="bottom"` — the API name "Drawer" is misleading; we re-export it as `BottomSheet` for clarity)
- Border-top-left/right radius: `var(--sheet-radius-top)` (16px). Bottom corners flush to viewport edge.
- Background: `var(--sheet-bg)` (Carbon Surface)
- Border: `1px solid var(--sheet-border)` on top edge only
- Z-index: `var(--z-sheet)` (320)
- Overlay: `var(--sheet-overlay)` `rgba(0,0,0,0.75)` (slightly darker than drawer overlay to differentiate stacked surfaces)
- Initial height: 90dvh (use `dvh` not `vh` to handle iOS soft-keyboard correctly — see PITFALLS §11)
- Snap points: P1 ships **no explicit snap points** — single full-height sheet that scrolls internally. (Snap points like 25%/50%/90% are a P5 concern when the chat composer needs partial visibility.)
- Padding-bottom: `var(--safe-bottom)` so footer clears iOS home indicator

**Drag handle:**
- Visible: 40px wide × 4px tall pill, `background: var(--sheet-handle)`, border-radius `var(--radius-full)`, centered horizontally, `margin-top: 8px`
- Touch zone: invisible 24px-tall band around the handle for grab tolerance
- `aria-label="Drag handle"` — the underlying div is not interactive via keyboard; close button in header is the keyboard path

**Sticky header:**
- Height: 56px content + 12px drag-handle band = ~68px total
- Padding: `var(--space-4)` (16px) horizontal, `var(--space-3)` (12px) vertical for content row
- Border-bottom: `1px solid var(--sheet-border)`
- Background: `var(--sheet-bg)` (opaque — content scrolls underneath, header stays solid)
- Layout: flex row — title left (`var(--font-size-md)` 16px, weight 600, `--color-text-primary`, truncate with ellipsis), close button right
- Close button: 36×36 button with 44×44 tap zone. Lucide `X` at 20px. `aria-label="Close"`

**Body (scrollable):**
- Padding: `var(--space-6)` (24px) — matches existing `.card-detail-header` and `.card-detail-main`
- Overflow: `overflow-y: auto`; scroll containment via `overscroll-behavior: contain` so swipe-to-scroll inside the sheet doesn't trigger sheet-close gesture above the content's scroll-top
- Hosts the same content the desktop modal hosts — the existing `CardDetailModal` body rendered as-is

**Sticky footer:**
- Height: 64px + `var(--safe-bottom)` padding-bottom for home indicator
- Padding: `var(--space-3)` (12px) vertical, `var(--space-4)` (16px) horizontal
- Border-top: `1px solid var(--sheet-border)`
- Background: `var(--sheet-bg)`
- Layout: flex row — secondary (Cancel) left, primary (Save) right; gap `var(--space-2)` (8px)
- The primary action is provided by the consumer via the `primaryAction` prop (label + onClick + disabled). Rendered as `.btn .btn-primary` from existing `globals.css` — visual parity with desktop Save/Confirm buttons.
- Cancel/secondary action: the close button doubles as cancel. Footer can render only a primary if no secondary needed.

**Dismissals:**
- Drag-down past 50% threshold (vaul `dismissible` default)
- Backdrop tap (vaul `modal={true}`)
- ESC key (Radix Dialog underneath)
- Close button tap
- Programmatic via `onClose()` after primary action completes

**`prefers-reduced-motion`:** vaul handles natively. Drag-to-close still works; the slide-in animation reduces to instant. Verified in vaul docs.

**Coexistence with existing `.card-detail-overlay`:** the existing `globals.css` already has a media query at line 528 collapsing `card-detail-body` to flex-column at `max-width: 768px`. **That media query stays** for content reflow. The change is: the OUTER overlay/modal-content at <768px is replaced by `<BottomSheet>` — the inner `card-detail-body` flex switches as before.

### 4. BottomTabBar (NEW per CONTEXT D-03/D-04/D-05)

Fixed bottom navigation at <768px. Renders ONLY when inside a project route (`/p/[projectId]/...`); hidden everywhere else.

**Anatomy:**

```
┌──────────────┬──────────────┬──────────────┐
│ [✓]          │ [📈]         │ [💬]         │
│ Plans        │ Runs         │ Chat         │  ← --bottom-tab-height (56px)
└──────────────┴──────────────┴──────────────┘
                                                ← safe-area-inset-bottom
```

**Specifics:**
- Position: `fixed; bottom: 0; left: 0; right: 0;`
- Height: `var(--bottom-tab-height)` (56px) + `var(--safe-bottom)` padding-bottom (iOS home indicator)
- Background: `var(--bottom-tab-bg)` (Carbon Surface)
- Border-top: `1px solid var(--bottom-tab-border)`
- Z-index: `var(--z-bottom-tab)` (250) — sits below modals and sheets so a sheet covers the tab bar entirely. (Some apps hide the tab bar when a sheet opens — for P1 we let the sheet's overlay cover it; visually equivalent.)
- Layout: `display: grid; grid-template-columns: repeat(3, 1fr);` — 3 equal cells; total width 100vw

**Tab cells (exactly 3 — locked by D-04):**

| Order | Key | Label | Icon | Href segment |
|-------|-----|-------|------|---------------|
| 1 | `plans` | **Plans** | lucide `ListChecks` | `/p/[projectId]/plans` (route lands in P4 — 404 in P1, expected) |
| 2 | `runs` | **Runs** | lucide `Activity` | `/p/[projectId]/runs` (route lands in P3 — 404 in P1, expected) |
| 3 | `chat` | **Chat** | lucide `MessageSquare` | `/p/[projectId]/chat` (route exists today) |

**Tab cell anatomy:**
- Tap target: full cell, 100% width × 56px height ≥ 44pt minimum
- Layout: flex column; `align-items: center; justify-content: center; gap: 2px;`
- Icon: 20px (`var(--bottom-tab-icon-size)`), color `var(--bottom-tab-color)` (inactive) or `var(--bottom-tab-color-active)` (active)
- Label: `var(--font-size-xs)` (12px) weight 500, color matches icon
- Padding: `8px 12px` (`--space-2 --space-3`)
- `:hover` (pointer-fine devices only via `@media (hover: hover) and (pointer: fine)`): icon + label color → `var(--color-text-primary)`. Honors PITFALLS §10 (hover-only on touch).
- `:focus-visible`: 2px outline `var(--color-accent)`, inset 2px so it doesn't bleed past cell edge
- `:active`: `transform: scale(0.96)` for tactile feedback (matches `.btn:active`)
- Active state: icon + label color → `var(--color-accent)` AND icon gets `filter: var(--bottom-tab-active-glow)`. **No fill, no underline, no top-bar indicator.** Color + glow only.
- Active detection: `pathname.startsWith('/p/' + projectId + '/' + segment)` — handled in component
- `aria-current="page"` on the active link

**Empty state (per D-05) — when no project selected:**
- BottomTabBar is rendered as a SEPARATE element below the topbar with the three tabs visible but DISABLED:
  - `pointer-events: none; opacity: 0.5;` on every tab cell
  - Tab labels remain visible (Plans/Runs/Chat) so the user understands what's available once a project is picked
  - Above the disabled tabs, in the page body, render an empty-state card: heading "Pick a project", body copy "Open the menu and choose a project to see Plans, Runs, and Chat for it.", primary CTA button "Open menu" that opens the Drawer.
- **Decision (consistent with the 01-04 plan task as written):** the 01-04 plan currently returns `null` from `BottomTabBar` when `projectId` is missing, and locates the empty-state copy on the primary view rather than within the bar itself. This UI-SPEC takes a SLIGHTLY different position — **the tab bar SHOULD be visible-but-disabled** so the user has a persistent visual hint of what's coming. **Action item for the planner:** reconcile with the executor before plan 01-04.5 ships; the contract test (case 5) checks the tab labels are exactly Plans/Runs/Chat, which both implementations satisfy. Either is acceptable but pick one and document.

**Hide-at-≥768px:** `@media (min-width: 768px) { .bottom-tab-bar { display: none } }` — pure CSS, no JS branch needed (avoids hydration flash). The component renders unconditionally; CSS hides it at desktop sizes.

**Hide-on-keyboard-up (forward declaration for P5):** when iOS soft keyboard opens (chat composer focus), the tab bar should hide so the composer can sit above the keyboard at viewport-bottom. **Phase 1 does NOT implement this** — `useVisualViewport` hook is scaffolded in P1 but consumed in P5. P1 ships the tab bar always-visible; PITFALLS §11 fix lands in P5 plan 05-01.

### Cross-cutting interactions

- **Tap-target ≥44×44pt** on every interactive element: hamburger, BottomSheet close, BottomSheet drag-handle band, every BottomTabBar cell, every Drawer item. Implemented via `min-height/min-width: var(--touch-target-min)` on cells AND `padding` on icon-only buttons. Phase 3 audit (MOB-09) will run the sweep across the whole app — Phase 1 primitives must already be compliant.
- **`:focus-visible` parity for every `:hover`:** every primitive declares `:focus-visible` styles equivalent to `:hover`. Phase 3 audit (MOB-10) sweeps the rest of the app; primitives lead by example.
- **`prefers-reduced-motion`:** every transition/animation gated by the existing `@media (prefers-reduced-motion: reduce)` query. vaul honors natively; custom CSS adds `transition: none; animation: none;` block.

- **Screen reader landmarks:**
