# Plan 01-01 — AgentRunEvent ledger + RunDiff + AgentTaskRun additions

## Goal

Establish the data model and write paths for the M1 run lifecycle. By the end of this plan a runner can:
1. Open a run (`startRun`) → row in `AgentTaskRun` with status='running', heartbeat=NOW(), `harnessSnapshotId` set (snapshot row written by 01-02 — placeholder UUID for the table to exist now).
2. Append events to `AgentRunEvent` as work happens — `tool_call_started`, `tool_call_succeeded`, `tool_call_failed`, `llm_message_in`, `llm_message_out`, `retry`, `side_effect`, etc. Append-only.
3. Capture `RunDiff` rows for every entity mutated, structured `{ before, after }` JSON.
4. Heartbeat at intervals (`runHeartbeat(runId)` updates `heartbeatAt` only).
5. Close a run (`finishRun`) → status terminal + summary text.

This plan ships **no runner integration** — the existing `runAgent` keeps working as before. Wiring `runAgent` to call into the new helpers happens in Phase 2 (so the ledger and bounded retries land together).

### Task 01-01.1 — Schema deltas + migration

**Files:**
- `prisma/schema.prisma`
- `prisma/migrations/20260502010000_add_run_lifecycle_substrate/migration.sql`

**Action:**

Three new models, plus column additions to `AgentTaskRun`. Indexes are non-trivial — write them deliberately because the audit UI (Phase 3) reads from them at scale.

```prisma
model AgentTaskRun {
  // existing fields unchanged…
  heartbeatAt        DateTime?
  harnessSnapshotId  String?          // FK; populated when 01-02 writes the snapshot
  summaryMd          String?  @db.Text
  harnessSnapshot    HarnessSnapshot? @relation(fields: [harnessSnapshotId], references: [id])
  events             AgentRunEvent[]
  diffs              RunDiff[]
}

model HarnessSnapshot {
  // Placeholder shape filled by 01-02 — minimal columns now so the FK from
  // AgentTaskRun resolves. 01-02 adds compiledPrompt, toolSchema, etc.
  id        String   @id @default(cuid())
  runId     String?  // optional back-ref; populated when 01-02 wires snapshotHarness
  createdAt DateTime @default(now())
  runs      AgentTaskRun[]
}

model AgentRunEvent {
  id        String   @id @default(cuid())
  runId     String
  run       AgentTaskRun @relation(fields: [runId], references: [id], onDelete: Cascade)
  // sequence number unique within a run — guarantees ordering even if two writes race
  // (Postgres UNIQUE on (runId, seq) + a server-side sequence per run; see migration SQL).
  seq       BigInt
  eventType String
  payload   Json
  createdAt DateTime @default(now())
  @@unique([runId, seq])
  @@index([runId, createdAt])
  @@index([eventType, createdAt])
}

model RunDiff {
  id         String   @id @default(cuid())
  runId      String
  run        AgentTaskRun @relation(fields: [runId], references: [id], onDelete: Cascade)
  // entity=card|comment|attachment|cardMember|chatChannel; entityId points at the row.
  entity     String
  entityId   String
  // null `before` → entity was created in this run; null `after` → entity was deleted.
  before     Json?
  after      Json?
  // Inverse-op data the Phase 3 revert UI replays. Optional now — Phase 3 fills in.
  inverseOp  Json?
  createdAt  DateTime @default(now())
  @@index([runId])
  @@index([entity, entityId])
}
```

Migration SQL (hand-written — Prisma can't introspect the per-run sequence cleanly):

```sql
ALTER TABLE "AgentTaskRun"
  ADD COLUMN "heartbeatAt" TIMESTAMP(3),
  ADD COLUMN "harnessSnapshotId" TEXT,
  ADD COLUMN "summaryMd" TEXT;

CREATE TABLE "HarnessSnapshot" (
  "id" TEXT NOT NULL PRIMARY KEY,
  "runId" TEXT,
  "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE "AgentRunEvent" (
  "id" TEXT NOT NULL PRIMARY KEY,
  "runId" TEXT NOT NULL,
  "seq" BIGINT NOT NULL,
  "eventType" TEXT NOT NULL,
  "payload" JSONB NOT NULL,
  "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT "AgentRunEvent_runId_fkey" FOREIGN KEY ("runId") REFERENCES "AgentTaskRun"("id") ON DELETE CASCADE
);
CREATE UNIQUE INDEX "AgentRunEvent_runId_seq_key" ON "AgentRunEvent"("runId", "seq");
CREATE INDEX "AgentRunEvent_runId_createdAt_idx" ON "AgentRunEvent"("runId", "createdAt");
CREATE INDEX "AgentRunEvent_eventType_createdAt_idx" ON "AgentRunEvent"("eventType", "createdAt");

CREATE TABLE "RunDiff" (
  "id" TEXT NOT NULL PRIMARY KEY,
  "runId" TEXT NOT NULL,
  "entity" TEXT NOT NULL,
  "entityId" TEXT NOT NULL,
  "before" JSONB,
  "after" JSONB,
  "inverseOp" JSONB,
  "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT "RunDiff_runId_fkey" FOREIGN KEY ("runId") REFERENCES "AgentTaskRun"("id") ON DELETE CASCADE
);
CREATE INDEX "RunDiff_runId_idx" ON "RunDiff"("runId");
CREATE INDEX "RunDiff_entity_entityId_idx" ON "RunDiff"("entity", "entityId");

ALTER TABLE "AgentTaskRun"
  ADD CONSTRAINT "AgentTaskRun_harnessSnapshotId_fkey"
  FOREIGN KEY ("harnessSnapshotId") REFERENCES "HarnessSnapshot"("id") ON DELETE SET NULL;
```

### Task 01-01.2 — Ledger writer module

**Files:** `src/lib/runEvents.ts` (new)

**Action:**

```ts
import prisma from './db';
import { z } from 'zod';

// Discriminated event type registry. Add to this list as new event kinds emerge.
// Phase 1 ships the core taxonomy; Phase 2 adds retry/cap_exceeded/mode_violation;
// Phase 4 adds out_of_plan_tool_call/amendment_cap_exceeded.
export const RUN_EVENT_TYPES = [
  'run_started', 'run_finished',
  'tool_call_started', 'tool_call_succeeded', 'tool_call_failed',
  'llm_message_in', 'llm_message_out',
  'side_effect', 'heartbeat',
] as const;
export type RunEventType = typeof RUN_EVENT_TYPES[number];

export const RunEventPayloadSchema = z.record(z.unknown()); // open-shape; per-type Zod schemas land in Phase 2

export async function appendRunEvent(
  runId: string,
  eventType: RunEventType | string, // string for forward-compat; new kinds added later
  payload: unknown,
): Promise<void> {
  // Append-only via per-run sequence. The unique (runId, seq) index makes
  // concurrent appends fail predictably; caller retries.
  // Postgres advisory lock on the runId hashCode would be cleaner — start with
  // `MAX(seq) + 1` inside a small transaction; revisit if contention shows up.
  await prisma.$transaction(async (tx) => {
    const max = await tx.agentRunEvent.aggregate({
      where: { runId },
      _max: { seq: true },
    });
    const nextSeq = (max._max.seq ?? BigInt(0)) + BigInt(1);
    await tx.agentRunEvent.create({
      data: { runId, seq: nextSeq, eventType, payload: payload as any },
    });
  });
}

export interface RunEventListOptions {
  limit?: number;
  afterSeq?: bigint;
  types?: string[];
}

export async function listRunEvents(runId: string, opts: RunEventListOptions = {}) {
  return prisma.agentRunEvent.findMany({
    where: {
      runId,
      ...(opts.afterSeq != null ? { seq: { gt: opts.afterSeq } } : {}),
      ...(opts.types && opts.types.length ? { eventType: { in: opts.types } } : {}),
    },
    orderBy: { seq: 'asc' },
    take: opts.limit ?? 200,
  });
}
```

**Verify:**
- Two concurrent `appendRunEvent` calls on the same `runId` either both succeed (with seq=1, seq=2) or one fails on the unique constraint and can be retried.
- `listRunEvents` returns rows in seq order even if `createdAt` is identical.

**Done:** atomic commit `feat(run): runEvents.ts — append-only ledger writer`.

### Task 01-01.3 — RunDiff snapshot helpers

**Files:** `src/lib/runDiffs.ts` (new)

**Action:**

```ts
import prisma from './db';

const ENTITY_LOADERS: Record<string, (id: string) => Promise<any>> = {
  card: async (id) => prisma.card.findUnique({ where: { id }, include: { members: true, checklists: { include: { items: true } } } }),
  comment: async (id) => prisma.comment.findUnique({ where: { id } }),
  attachment: async (id) => prisma.attachment.findUnique({ where: { id } }),
  cardMember: async (id) => prisma.cardMember.findUnique({ where: { id } }),
  chatChannel: async (id) => prisma.chatChannel.findUnique({ where: { id } }),
};

export type DiffableEntity = keyof typeof ENTITY_LOADERS;

export async function snapshotEntity(entity: DiffableEntity, id: string) {
  const loader = ENTITY_LOADERS[entity];
  if (!loader) throw new Error(`No diff loader for entity: ${entity}`);
  return loader(id);
}

export async function commitRunDiff(opts: {
  runId: string;
  entity: DiffableEntity;
  entityId: string;
  before: any | null;
  after: any | null;
}) {
  return prisma.runDiff.create({
    data: {
      runId: opts.runId,
      entity: opts.entity,
      entityId: opts.entityId,
      before: opts.before,
      after: opts.after,
    },
  });
}
```

**Verify:**
- `snapshotEntity('card', cardId)` returns the card with members + checklists + items.
- `commitRunDiff({ before: null, after: {...} })` represents a creation.
- `commitRunDiff({ before: {...}, after: null })` represents a deletion (the negative-space rendering target for AUD-04).

**Done:** atomic commit `feat(run): runDiffs.ts — entity snapshot helpers`.

### Task 01-01.4 — Run heartbeat + lifecycle helpers

**Files:** `src/lib/runHeartbeat.ts` (new)

**Action:**

```ts
import prisma from './db';
import { appendRunEvent } from './runEvents';

export interface StartRunOpts {
  agentId: string;
  projectId?: string | null;
  cardId?: string | null;
  harnessSnapshotId?: string | null; // populated by 01-02 once snapshotHarness lands
  kind?: string;
}

export async function startRun(opts: StartRunOpts) {
  const run = await prisma.agentTaskRun.create({
    data: {
      agentId: opts.agentId,
      projectId: opts.projectId ?? null,
      cardId: opts.cardId ?? null,
      kind: opts.kind ?? 'manual',
      status: 'running',
      heartbeatAt: new Date(),
      harnessSnapshotId: opts.harnessSnapshotId ?? null,
    },
  });
  await appendRunEvent(run.id, 'run_started', {
    agentId: opts.agentId, kind: run.kind, harnessSnapshotId: opts.harnessSnapshotId ?? null,
  });
  return run;
}

export async function heartbeat(runId: string) {
  await prisma.agentTaskRun.update({ where: { id: runId }, data: { heartbeatAt: new Date() } });
  // Heartbeat events are append-only and frequent — keep payload tiny.
  await appendRunEvent(runId, 'heartbeat', {});
}

export async function finishRun(runId: string, status: 'succeeded' | 'failed' | 'cancelled', summary?: string) {
  await prisma.agentTaskRun.update({
    where: { id: runId },
    data: {
      status,
      heartbeatAt: new Date(),
      summaryMd: summary ?? null,
    },
  });
  await appendRunEvent(runId, 'run_finished', { status, summary: summary ?? null });
}
```

**Verify:**
- `startRun` creates an `AgentTaskRun` with status='running' AND a `run_started` event with seq=1.
- `heartbeat` updates `heartbeatAt` AND appends a `heartbeat` event.
- `finishRun` flips status terminal AND appends `run_finished`.
- Status field on `AgentTaskRun` is a denormalized projection — reading the latest event from `listRunEvents` of type `run_finished` should agree with it.

**Done:** atomic commit `feat(run): runHeartbeat.ts — startRun / heartbeat / finishRun`.

## Risks + mitigations

- **Risk:** Per-run `seq` allocation race. Two concurrent appends both read MAX(seq)=N, both insert seq=N+1, one fails on the unique constraint.
  **Mitigation:** Caller retries. `appendRunEvent` should be wrapped in a Phase 2 retry layer; for Phase 1, document and live with it. The tests cover the JS intent; SQL-level race handling is Phase 2.
- **Risk:** RunDiff payload bloat. Capturing a card with all checklist items + members on every mutation could hit Postgres JSONB limits at scale.
  **Mitigation:** Phase 1 only enables capture; runner doesn't yet call `commitRunDiff` automatically. Phase 3 will introduce per-tool size limits + truncation. Punt now.
- **Risk:** `HarnessSnapshot` table has placeholder shape — 01-02 fills it in, but if 01-02 changes the column set, the migration here would need updating.
  **Mitigation:** Coordinate sequencing — 01-01 lands first, 01-02's migration ADDs to HarnessSnapshot rather than restructuring it. Document this in 01-02's plan.
