# Plan 01-03 — Instrumentation registration

## Goal

Make every LLM call traceable without forcing each plugin handler to instrument. One file (`instrumentation.ts`) that Next.js 16 auto-loads at boot; one set of env vars to opt in; one commented stanza in `docker-compose.yml` to spin up self-hosted Langfuse.

## Why this is its own plan

Cross-cutting. Touches no app code beyond the LLM-call boundary. Independent of 01-01 (ledger) and 01-02 (harness) — those tracks ship first; this plan can land any time after `package.json` deps are installed. Parallelizable with 01-04 (mobile) too.

## Tasks

**Files:**

**Action:**

`instrumentation.ts`:

```ts
import { registerOTel } from '@vercel/otel';

// Next.js 16's instrumentation.ts entry point. Called once at server boot.
// All wiring is env-gated; the no-env-vars case is a no-op and existing
// runs proceed unchanged.

export function register() {
  if (process.env.OTEL_EXPORTER_OTLP_ENDPOINT) {
    registerOTel({
      serviceName: process.env.OTEL_SERVICE_NAME || 'co-op',
      // OTel auto-detects the exporter from OTEL_EXPORTER_OTLP_ENDPOINT;
      // works against Langfuse's OTLP endpoint, Honeycomb, Tempo, etc.
    });
  }

  // Langfuse SDK registration is lazy — the singleton is created on first import
  // by src/lib/observability/langfuse.ts. We don't import it here; that would
  // pull in transitive deps even when LANGFUSE_PUBLIC_KEY isn't set.
}
```

**Verify:**
- `npm run build` succeeds with the new deps.
- Without `OTEL_EXPORTER_OTLP_ENDPOINT` set, `registerOTel` is not called; no console output, no extra span exporters.

**Done:** atomic commit `feat(obs): instrumentation.ts entry point + OTel + Langfuse deps`.

### Task 01-03.2 — Langfuse client singleton

**Files:** `src/lib/observability/langfuse.ts` (new)

**Action:**

```ts
import { Langfuse } from 'langfuse';

let cached: Langfuse | null = null;
let probed = false;

export function getLangfuse(): Langfuse | null {
  if (probed) return cached;
  probed = true;
  if (!process.env.LANGFUSE_PUBLIC_KEY || !process.env.LANGFUSE_SECRET_KEY) return null;
  cached = new Langfuse({
    publicKey: process.env.LANGFUSE_PUBLIC_KEY,
    secretKey: process.env.LANGFUSE_SECRET_KEY,
    baseUrl: process.env.LANGFUSE_HOST || 'https://cloud.langfuse.com',
  });
  return cached;
}

// Convenience: trace a generation. Wraps a Promise-returning fn and emits a
// langfuse 'generation' span. No-op when langfuse is unconfigured.
export async function traceGeneration<T>(
  opts: {
    name: string;
    model: string;
    input: any;
    metadata?: Record<string, any>;
    runId?: string | null;
    agentId?: string | null;
  },
  fn: () => Promise<{ result: T; usage?: { inputTokens?: number; outputTokens?: number } }>
): Promise<T> {
  const lf = getLangfuse();
  if (!lf) {
    const { result } = await fn();
    return result;
  }
  const trace = lf.trace({
    name: opts.runId ? `run/${opts.runId}` : opts.name,
    metadata: { agentId: opts.agentId, ...opts.metadata },
  });
  const gen = trace.generation({
    name: opts.name,
    model: opts.model,
    input: opts.input,
  });
  try {
    const { result, usage } = await fn();
    gen.end({ output: result, usage });
    return result;
  } catch (err) {
    gen.end({ output: { error: String(err) }, level: 'ERROR' });
    throw err;
  }
}
```

**Verify:** With env vars unset, `getLangfuse()` returns null; `traceGeneration` runs `fn()` and returns its result without emitting traces.

**Done:** atomic commit `feat(obs): Langfuse client singleton + traceGeneration wrapper`.

### Task 01-03.3 — Wrap Anthropic / OpenAI / CLI calls

**Files:** `src/lib/agentRunner.ts` (existing — wrap the runAnthropic / runOpenAI inner calls)

**Action:** Locate the inner Anthropic + OpenAI client calls in `agentRunner.ts` (search for `client.messages.create` / `client.chat.completions.create`). Wrap each in `traceGeneration`. Pass `runId` (Phase 1 doesn't yet have a stable `runId` for non-card runs — pass `null` for now; Phase 2 hooks it up via `runHeartbeat.ts:startRun`).

```ts
// before:
const res = await anthropic.messages.create({ ... });

// after:
const res = await traceGeneration(
  { name: 'anthropic.messages.create', model: agent.modelName, input: { system, messages }, agentId: agent.id, runId: opts.runId ?? null },
  async () => {
    const r = await anthropic.messages.create({ ... });
    return { result: r, usage: { inputTokens: r.usage?.input_tokens, outputTokens: r.usage?.output_tokens } };
  }
);
```

Same shape for the OpenAI path. The CLI runner (`src/lib/agentCliRunner.ts`) gets a thinner wrapper because there's no token usage to report — just span boundaries.

**Verify:** With Langfuse env unset, behavior is byte-identical; no extra round-trips. With env set, a single agent run produces one trace with N generation spans (N = number of LLM round-trips).

**Done:** atomic commit `feat(obs): wrap Anthropic/OpenAI/CLI calls with Langfuse generation spans`.

## Risks + mitigations

- **Risk:** Adding `langfuse` as a regular dependency pulls in transitive deps that bloat the cold-boot time even when unused.
  **Mitigation:** The singleton in `langfuse.ts` is import-lazy — the SDK module is only loaded when env vars are set. Verified by `npm run build` size delta + a manual cold-boot test.
- **Risk:** `@vercel/otel` is opinionated about Next.js runtime version; React 19 + Next.js 16 may need a specific version.
  **Mitigation:** The locked version in research SUMMARY.md (`^2.1.2`) is verified against Next.js 16.2.3. If it breaks, downgrade to a minor that's known-good.
- **Risk:** Wrapping every LLM call increases latency under high load.
  **Mitigation:** When Langfuse env is unset, `traceGeneration` is a no-op (single conditional branch). When set, the SDK batches and ships out-of-band; no synchronous round-trip.
